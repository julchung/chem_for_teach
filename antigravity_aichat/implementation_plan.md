# AI 化學伴讀系統 (AI Tutor) - 多智能體架構計畫書

本計畫書旨在記錄 AI 化學伴讀系統的介面設計與本地多智能體 (Multi-Agent) 協作架構方針，作為後續開發的依據與備忘錄。

## 🎯 系統目標與受眾
- **核心目標**：打造一個左側為「教學圖文/動畫展示區」，右側為「AI 聊天室」的雙欄互動介面。
- **目標受眾**：高中至大二學生。系統需具備親切的引導語氣，並將複雜的化學概念轉換為易懂的視覺化圖表。

## 💻 使用者介面設計 (UI/UX)
- **整體架構**：雙欄式佈局 (Split-Pane)
- **左欄 (教學展示區)**：
  - 佔據畫面約 60% 寬度。
  - 初始為空狀態，負責接收並渲染 AI 輸出的圖文、HTML、SVG 繪圖代碼或 Chart.js 數據。
  - 支援分頁 (Tabs) 功能，可保留歷史教學投影片。
- **右欄 (聊天對話區)**：
  - 佔據畫面約 40% 寬度。
  - 包含：對話歷史紀錄、Ollama 模型選擇器（可切換「自動多模型路由」或「單一模型」）、文字與多媒體（圖片/語音）輸入區。

## 🤖 本地 Ollama 模型配置 (單一全能視覺模型策略)

考量一般電腦硬體限制 (16GB RAM) 以及**支援「圖片與檔案上傳解析」**的需求，系統將採用「單一強大多模態模型」搭配「不同 System Prompt 分飾多角」的極速方案，避免頻繁切換模型的卡頓。

### 核心全能模型：Llama 3.2 Vision (11B) 或 MiniCPM-V
- **推薦模型**：`llama3.2-vision:11b` (Meta 最新視覺模型，邏輯與讀圖極強) 或 `minicpm-v` (中文 OCR 解析能力頂尖)。
- **任務 1 (視覺與接待)**：解讀學生上傳的圖片（如考卷截圖、實驗照片），並親切對話。
- **任務 2 (幕後大腦)**：負責深度的化學機制推演與數理邏輯計算。
- **任務 3 (繪圖師)**：將解說文字轉換為 SVG 或 Chart.js 程式碼供左側渲染。

## 🔄 系統資料流與互動流程
為了讓三個本地模型能無縫合作，前端應用程式將扮演「總指揮」的角色：

1. **輸入與解析**：
   - **文字/圖片**：學生在右側輸入問題或上傳圖片。圖片將由前端轉為 Base64 格式。
   - **文件檔案 (PDF/Word/TXT)**：前端將透過 JavaScript 解析萃取檔案內的文字內容，附加在對話中送出。
2. **路由分配**：前端 JavaScript 呼叫核心模型。若屬教學問題，則提取關鍵字並往下傳遞。
3. **推演**：前端將提問發送給 **Model 2 (幕後大腦)**，產出詳細且具備教學邏輯的文字解答。
4. **並行渲染**：
   - 前端將 Model 2 的解答文字顯示於 **右側聊天框**。
   - 同時，前端將解答作為提示詞發送給 **Model 3 (繪圖師)**，要求生成 SVG/HTML 代碼。
   - Model 3 的程式碼回傳後，前端動態將其注入並顯示於 **左側展示區**。

## 🛠️ 開發技術棧
- **前端實作**：HTML5, CSS3, Vanilla JavaScript (或後續視複雜度導入 React/Vue)。
- **後端與 AI 串接**：網頁前端直接透過 Fetch API 呼叫本地端 Ollama 服務 (`http://localhost:11434/api/generate`)。*(需設定 Ollama 允許跨網域請求 CORS)*
- **視覺化工具**：原生 SVG、Chart.js (適合繪製滴定曲線等數據圖)。
